# Copy — frameworks narrativos (formato) e objetivos

Camada geral, vale para qualquer negócio. Complementa `CONTEXT.md` (espinha e
leis de qualidade) e `knowledge/copy/negocios/<business>.md` (o que dizer neste
setor).

**Framework ≠ arco.** O framework dá o **formato** (quantos slides, o que entra
em cada um); o arco dá o **sabor emocional** (validação, mito→verdade,
provocação — ver a gramática do acervo no dossiê do negócio). Declare os dois
no `dossie.md`.

**Formato por slide é obrigatório.** Além do framework da peça inteira, cada
slide declara o seu formato (`gancho`, `tese+ressalva`, `enumerado`, `passo`,
`comparacao`, `mito-verdade`, `pergunta-resposta`, `dado`, `citacao`, `cta`) e
o papel de cada pedaço de texto — ver o modelo em `CONTEXT.md` → "Saída:
dossie.md". É isso que o designer usa para escolher o tratamento; sem declarar,
ele recebe strings soltas e inventa uma hierarquia. Antes de escrever, leia
`comporta` no `pack.json`: escrever um enumerado de 6 itens para um pack que
resolve 3 é erro de briefing, não do designer.

## Objetivos (escolha 1 por peça)

| Objetivo | Serve para | Mede-se por | Frameworks fortes | Evite |
|---|---|---|---|---|
| `aquisicao` | atrair quem não conhece | alcance fora dos seguidores, shares | listicle, PAS, mito-vs-verdade | vulnerável, bastidor |
| `posicionamento` | mostrar ponto de vista próprio | comentários de debate, menções | contrarian, framework-reveal, dado+interpretação | cheat-sheet, listicle simples |
| `engajamento` | saves/comentários com quem já segue | save rate, comment rate | listicle salvável, erros-a-evitar, cheat-sheet | vulnerável |
| `educacao` | ensinar algo prático | saves, swipe completo | passo-a-passo, framework-reveal, antes-depois | contrarian |
| `prova_social` | validar autoridade sem vender | DMs "como você fez", shares | case-study, antes-depois, mini-FAQ | listicle puro |
| `retencao` | fortalecer relação com a base | comentários longos, DMs | vulnerável, bastidor, mini-FAQ | dado frio, cheat-sheet |

## Os 14 frameworks (arco slide-a-slide)

| Framework | Slides | Estrutura |
|---|---|---|
| `listicle` | 6–9 | capa (número+categoria) → setup opcional → 1 item por slide (hierarquia igual) → CTA salvar/comentar |
| `myth-vs-truth` | 5–7 | capa "N mitos" → mito 1 → verdade 1 (+evidência) → repete → fechamento compartilhar. **O mito tem que ser algo que a audiência realmente acredita** |
| `step-by-step` | 5–8 | capa "como X em N passos" → promessa → 1 passo por slide (verbo + instrução) → recap + salvar |
| `problem-agitate-solve` | 3–5 | problema reconhecível → por que é mais sério → direção da solução (não o tutorial) → próximo passo |
| `contrarian-take` | 4–6 | crença comum → pivot ("mas o problema é") → sua tese → raciocínio → implicação prática → CTA debate |
| `framework-reveal` | 5–7 | nome do método + benefício → problema que resolve → 1 pilar por slide → como aplicar amanhã. **Nome curto e memorável** |
| `mistakes-to-avoid` | 5–8 | capa "N erros" → erro + "em vez disso:" correção (1 por slide) → "qual você já cometeu?" |
| `case-study-narrative` | 5–7 | tease antes→depois → contexto → desafio → ação → resultado → lição generalizada → CTA |
| `before-after-transformation` | 3–5 | capa antes/depois → estado inicial → o que mudou → estado final → como replicar |
| `cheat-sheet` | 1–3 | capa com densidade visível → tabela/grid/mapa → como usar + salvar. **Densidade alta exige hierarquia forte** |
| `data-driven-insight` | 4–6 | stat + contexto → fonte/população → por que acontece (seu POV) → implicação → CTA |
| `vulnerable-story` | 5–7 | confissão → contexto → o erro → consequência → virada → lição → CTA conversa |
| `behind-the-scenes` | 4–6 | "por dentro de X" → por que importa → 2–3 revelações → insight → CTA |
| `mini-faq` | 4–6 | "as N perguntas que mais recebo" → P + R por slide (2–4 linhas) → "tem outra? comenta" |

## Réguas de formato

- **6–10 slides** é a faixa de educação profunda; 3–5 serve peça rápida/PAS;
  1–3 só para cheat-sheet. Menos de 4 performa como imagem única.
- **Slides 1 e 2 decidem a distribuição**: se não seguram o swipe, o resto não
  é visto. O gancho para de rolar em 1–2 segundos.
- **Save e share pesam mais que like**: prefira CTAs que peçam salvar,
  compartilhar ou marcar alguém — e só peça o que a peça mereceu.
- Não force um framework: listicle com 5 itens quando o tema tem 3 dilui.

## Compliance

Nada aqui sobrepõe `compliance/<vertical>.md` nem as leis do §3b do CONTEXT:
frameworks de prova (case-study, antes-depois, dado) em saúde vivem com modais
e sem promessa de resultado — o arco `antes-depois-ponte` é o mais seguro.
